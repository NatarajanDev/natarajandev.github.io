# Nova CMS — PHP + SQLite content platform

An advanced content management system with a public front end **and** a full admin panel, written in
plain PHP 8 and backed by a single SQLite file. No Composer packages, no framework, no build step —
clone it, run two commands and you have a working CMS.

```bash
php bin/install.php --email=you@example.com --password=your-password --demo
php -S localhost:8080 -t public public/router.php
```

Then open <http://localhost:8080> for the site and <http://localhost:8080/admin> for the panel.

> Portfolio sample. All content is synthetic demo data generated by the seeder. There is no client
> code, no proprietary source and no shipped credentials — you create the first administrator account
> during install.

## What it demonstrates

| Area | Highlights |
|---|---|
| Architecture | Front controller, custom router with named routes + middleware, lazy service container, repository layer, view layer with layouts/partials |
| Database | SQLite by default (MySQL optional), migration runner with a `migrations` ledger, schema builder that emits SQLite or MySQL DDL from one definition |
| Content | Markdown authoring, revisions with restore, drafts/scheduled/published workflow, bulk actions, categories (nested) and tags (with merge) |
| Admin panel | Dashboard with analytics, posts, pages, taxonomy, comment moderation, media library, users & roles, settings, maintenance tools, audit trail |
| Public site | Home, blog index, category/tag/author/month archives, search (+ live JSON search), article pages, threaded comments, RSS 2.0, JSON Feed, `sitemap.xml`, `robots.txt` |
| Security | Prepared statements everywhere, CSRF tokens on every write, bcrypt/argon2 hashing, login throttling, role checks, MIME-sniffed uploads, escaped output |
| Zero dependencies | Only PHP extensions: `pdo_sqlite`, `mbstring`, `fileinfo`, `gd` (thumbnails) |

## Quick start

**Requirements:** PHP 8.1+ with the extensions listed above. Nothing else.

```bash
cd projects/php-sqlite-cms

# 1. create the database, run migrations and create your administrator
php bin/install.php --name="Jane Doe" --email=jane@example.com --password=secret-password --demo

# 2. serve it (document root must be public/)
php -S localhost:8080 -t public public/router.php
```

* Site → <http://localhost:8080>
* Admin panel → <http://localhost:8080/admin>
* Installer checklist (requirements + database status) → <http://localhost:8080/install>

Omit `--demo` for an empty site. `php bin/install.php --help` lists every option, and
`--reset` drops all tables before migrating (destructive, useful while developing).

On shared hosting: upload the folder, point the domain's document root at `public/`, then run the
installer in the browser (`/install`) — it verifies extensions, directory permissions and runs the
migrations for you.

## Features

### Public front end
* **Home** — hero, featured articles, latest posts, category grid.
* **Blog index** with pagination and sorting, plus **archives** by category, tag, author and month.
* **Search** — server-rendered results and a debounced live-search endpoint (`/api/search`).
* **Article pages** — Markdown rendering, table of contents friendly headings, reading-progress bar,
  cover images, related posts, previous/next navigation, per-article view counters.
* **Comments** — threaded, honeypot + time-trap + per-IP rate limiting + duplicate detection,
  moderation queue when enabled.
* **Feeds** — `/feed.xml` (RSS 2.0), `/feed.json` (JSON Feed 1.1), `/sitemap.xml`, `/robots.txt`.
* **Dark/light theme** toggle (no flash of unstyled content), responsive layout, print styles.

### Admin panel (`/admin`)
* **Dashboard** — post/comment/user totals, 14-day views chart, storage usage, pending moderation,
  recent activity timeline. Authors see only their own content.
* **Posts** — create/edit with a Markdown editor (write / preview / split), autosave-friendly slug
  field, tags, categories, cover image picker, SEO fields, scheduling, revisions with restore,
  bulk publish/draft/feature/delete.
* **Pages** — flat and nested pages, menu visibility, ordering, custom templates, SEO fields.
* **Taxonomy** — categories with parent/child nesting and colours; tags with usage counts and merge.
* **Comments** — approve, unapprove, spam, trash, delete, reply inline, bulk moderation.
* **Media library** — drag-and-drop uploads, thumbnails, alt text, captions, search/filter, and a
  picker modal that other screens use to choose images.
* **Users & roles** — `admin` (everything), `editor` (all content), `author` (own content only);
  avatar, bio, socials; guards against self-demotion and deleting the last administrator.
* **Profile** — update details, change password (verifies the current one, revokes remember-me tokens).
* **Settings** — six tabs (general, content, comments, appearance, SEO, social) with typed fields.
* **Tools** — flush cache, run pending migrations, prune logs/audit/attempts, download an SQLite
  backup, export all content as JSON, tail application logs, browse the audit trail.

## Configuration

Every value has a working default, so configuration is optional. Copy `.env.example` to
`config/config.local.php` (array form) or export the variables in your web server, Docker container
or hosting panel.

| Variable | Default | Purpose |
|---|---|---|
| `CMS_APP_NAME` | `Nova CMS` | Brand shown in titles |
| `CMS_ENV`, `CMS_DEBUG` | `production`, `false` | Error display and logging verbosity |
| `CMS_URL` | `http://localhost:8080` | Absolute URL for canonical links, feeds, sitemap |
| `CMS_TIMEZONE` | `UTC` | Display timezone |
| `CMS_STORAGE_PATH` | `storage/` | Writable dir for logs, cache, sessions |
| `CMS_DB_DRIVER` | `sqlite` | `sqlite` or `mysql` |
| `CMS_DB_PATH` | `storage/cms.sqlite` | SQLite file location |
| `CMS_DB_HOST/PORT/NAME/USER/PASS` | — | MySQL connection when `CMS_DB_DRIVER=mysql` |
| `CMS_LOGIN_MAX_ATTEMPTS`, `CMS_LOGIN_LOCKOUT` | `5`, `15` | Login throttling window |
| `CMS_UPLOAD_MAX_BYTES` | `5242880` | Maximum upload size |

## Scheduled maintenance

```cron
*/5 * * * * php /path/to/php-sqlite-cms/bin/cron.php >> /dev/null 2>&1
```

`bin/cron.php` publishes scheduled posts, clears content caches and prunes old logs, login attempts
and audit rows.

## Tests

No PHPUnit required — a self-contained runner creates a throwaway SQLite database, runs the real
migrations and exercises the stack end to end:

```bash
php tests/run.php              # everything
php tests/run.php security     # only suites whose name matches
php tests/run.php repository/p # single suite
```

| Suite | Covers |
|---|---|
| `support/strings`, `support/markdown`, `support/validator`, `support/cache`, `support/response` | Helpers, Markdown → HTML (including XSS escaping), validation rules, file cache, HTTP responses |
| `database/migrations` | Migration runner, idempotency, expected tables |
| `repository/*` | Settings, users, taxonomy, posts (filters, tags, revisions, analytics, bulk), comments (threading, moderation, spam guards), media, messages |
| `service/installer+auth` | Installer, demo seeding, idempotent re-seed, login, throttling, remember-me |
| `service/dashboard+feeds` | Dashboard aggregates, RSS/JSON feeds, sitemap, audit log |
| `security/csrf+sessions`, `security/uploads`, `security/access-control` | CSRF rotation, upload hardening (disguised scripts, oversize, thumbnails), router middleware and role gates |
| `views/rendering` | 404 page, home, article and login templates render outside the web server |

CI runs the suite plus an HTTP smoke test on PHP 8.3 for every push
(`.github/workflows/php-sqlite-cms.yml`).

## Project layout

```
php-sqlite-cms/
├── bin/                    install.php, cron.php (CLI entry points)
├── config/config.php       single configuration file (env-overridable)
├── database/migrations/    001…005 — schema as code
├── public/                 ← web root
│   ├── index.php           front controller
│   ├── router.php          PHP built-in server router
│   ├── .htaccess           Apache rewrite + hardening rules
│   ├── assets/{css,js,img} hand-written CSS/JS, inline SVG icons
│   └── uploads/            media library files (created at runtime)
├── src/
│   ├── bootstrap.php       autoloader, error handling, session, helpers
│   ├── App.php             lazy service container
│   ├── Controllers/        Site/ (public) and Admin/ (panel) controllers
│   ├── Database/           Connection, Schema builder, Migrator
│   ├── Repository/         one class per table group — all SQL lives here
│   ├── Service/            Installer, DashboardStats, Feed, Sitemap, ActivityLog
│   └── Support/            Router, Request, Response, Auth, View, Validator,
│                           Markdown, Csrf, Paginator, Uploader, Cache, helpers
├── storage/                logs, cache, sessions, SQLite file (writable)
├── tests/run.php           dependency-free test runner
└── views/                  layouts/, site/, admin/, partials/, auth/, errors/
```

**Request lifecycle:** `public/index.php` → bootstrap (config, container, session) → `Router`
matches the path → middleware (`auth`, `guest`, `role:x`, `csrf`) → controller → repositories →
`View` renders a template inside a layout → `Response` is sent with security headers.

## Security notes

* Every query is a prepared statement — no string interpolation of user input into SQL.
* All state-changing routes sit behind a `csrf` middleware that compares a per-session token.
* Passwords use `password_hash()` with rehash-on-login; the hash never leaves the repository layer.
* Login is throttled per email + IP; failed attempts are logged and pruned by cron.
* Uploads are validated by sniffed MIME type (not extension), renamed, stored outside the routing
  surface and given generated filenames; `.sqlite`/`.log`/`.sql` are denied by the shipped `.htaccess`.
* Output is escaped through `e()`; Markdown is rendered from an escaping parser, so raw HTML in
  content cannot inject script.
* Roles are enforced in middleware *and* per-row (authors can only touch their own posts), and
  administrators cannot demote or delete themselves out of the system.

### Deploying

Point the document root at `public/`, make `storage/` and `public/uploads/` writable by the PHP user,
then run `php bin/install.php` (or visit `/install`). Nginx equivalent of the shipped rules:

```nginx
root /var/www/php-sqlite-cms/public;
location / { try_files $uri $uri/ /index.php?$query_string; }
location ~ \.php$ { include snippets/fastcgi-php.conf; fastcgi_pass unix:/run/php/php8.3-fpm.sock; }
location ~* \.(sqlite|sql|log)$ { deny all; }
```

Keep the SQLite file (and `storage/`) **outside** the document root so it can never be downloaded,
and back it up with the admin **Tools → Download backup** button before upgrades.
